\begin{abstract}
    In questo documento vengono presentati i risultati della pulizia finale del database,
    con l'elenco delle tabelle che sono state mantenute, eliminate o modificate, e le motivazioni alla base di queste decisioni.
\end{abstract}
\section{Tabelle risultati della pulizia finale}

\subsection{Agenti}(Eliminare gestita con tabella utenti)

\subsection{autori\_offerte}(Diventa la tabella utenti)
Tabella che raccoglie tutti i possibili autori delle offerte di vendita, attualmente sostituibile con una tabella degli utenti.
La tabelle deve avere un campo per identificare il ruolo dell'utente (agente, cliente, ecc.),
in modo da poter gestire mediante questa tabella sia gli agenti che, all'interno delle offerte, gli autori, i riferimenti interni ed esterni, ecc.
La tabella utenti può essere popolata anche da contatti che non usano direttamnete il software, ma che possono essere utilizzati come riferimento per le offerte.
\begin{lstlisting}
    CREATE TABLE [dbo].[autori_offerte] (
    [aof_id]         INT             IDENTITY (1, 1) NOT NULL,
    [aof_nome]       NVARCHAR (60)   NULL,
    [aof_sigla]      NVARCHAR (3)    NULL,
    [aof_firma]      VARBINARY (MAX) NULL,
    [creation_date]  DATETIME        NULL,
    [creation_user]  INT             NULL,
    [last_edit_date] DATETIME        NULL,
    [last_edit_user] INT             NULL,
    [deleted]        BIT             DEFAULT ((0)) NULL,
    CONSTRAINT [autori_offerte$PrimaryKey] PRIMARY KEY CLUSTERED ([aof_id] ASC),
    CONSTRAINT [SSMA_CC$autori_offerte$aof_sigla$disallow_zero_length] CHECK (len([aof_sigla])>(0)),
    CONSTRAINT [SSMA_CC$autori_offerte$aof_nome$disallow_zero_length] CHECK (len([aof_nome])>(0))
);
\end{lstlisting}

e un campo padre per la ricostruzione, in modo da permettere
